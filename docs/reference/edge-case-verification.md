# Edge-case verification

**Type:** Reference (Diátaxis) · **Last verified:** 2026-11-14 (branch `verify-1-edge-cases`, on M0–M2 and UX-1) · **Source:** Scalable MVP Stack, §Edge cases (22 rows), §Resilience and disaster recovery, §Security and compliance controls (confidential, cited by section only, [ADR-0008](../adr/ADR-0008-interim-hosting-and-confidentiality.md))

The reference architecture wants each of its 22 edge cases to have a documented rule, and a test or a drill, by go-live. This page records, for each case, the rule Sauti follows, the test or drill behind it, and where Sauti's rule differs from the reference on purpose. The same is done for the failure modes of the resilience and security sections that a test can exercise.

**Status values:**
- **Verified:** an existing test proves the rule.
- **Added:** this verification added the test that proves it (each one was first made to fail by breaking the behaviour it checks).
- **Gap:** the code does not do what the reference asks, and a test or finding records the exact behaviour.
- **M3–M7, P0:** a later phase of `docs/superpowers/plans/2026-11-12-phased-roadmap.md` delivers it, or it is proven by an infrastructure drill.

A test pointer is `file::TestName`; `::TestName` repeats the file before it. Integration tests need `-tags integration`.

## Findings

**G-1 · Medium · A call dropped before the ward is flagged, and nobody is rung, unless it was danger-yes or red.** If the caller answered no to the danger question, was not classified red, and hung up before choosing a ward, the sweeper writes only `incident.flagged` with `abandoned` (and `abandoned_before_category` when no category was given). No escalation is recorded, so the coordinator line does not ring, and no list shows the call. A yellow call (for example poisoning with no danger sign at screen 5) dropped at screen 6 is one such call. `internal/intake/sweeper_test.go::TestSweeperBeforeTheWardStillOnlyFlags` pins this behaviour. The rule follows Build Prompt §10.3, which names only the danger-yes call-back, and ADR-0029 rule 3, which escalates once a ward is known. The reference expects a coordinator call-back for every caller who disconnects before saying where they are. Not fixed here: which abandoned calls ring a coordinator is a protocol decision for the PI behind the amendment gate (with R-9), and escalating every pocket dial would flood the coordinator line. A call-back also needs the M5 audited reveal.
