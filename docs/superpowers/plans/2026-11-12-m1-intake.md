# M1 Intake and Triage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A caller completes Tool 1 on USSD (on either route) or IVR. The answers are triaged deterministically, the location is resolved to a 500 m zone, and duplicates are merged. Each step is persisted the moment it is given, and the flow proves scenarios 3–6.

**Architecture:** One channel-agnostic Tool 1 state machine (`internal/intake`) drives both USSD and IVR. Every answer becomes a `screen.answered` event through the single write path. Severity comes from a signed CEL decision table (`internal/triage`). Location comes from a UTM 36N grid and a gated gazetteer with `pg_trgm` fuzzy matching (`internal/location`). Identifiers in answers are sealed, never logged, and never hashed without a key.

**Tech Stack:** Go 1.27.4, PostgreSQL 18.6 (`pg_trgm`), `cel.dev/cel-go` v0.33.2, `github.com/coder/websocket` v1.8.15 (Part C), sqlc v1.31.1.

**Spec:** `docs/superpowers/specs/2026-11-12-sauti-dispatch-design.md` (§4.3, §7, §11 M1), roadmap phase 2 (`docs/superpowers/plans/2026-11-12-phased-roadmap.md`).

## Global Constraints

- The 14 hard constraints in Build Prompt §3. In particular:
  - triage is deterministic, and nothing lowers a severity (3);
  - the database sets all T-times (4);
  - the caller's number never appears in payloads, logs or step keys (5, 8);
  - dispatch comes first, and the system fails safe to a human (14).
- **Clinical content is a placeholder** (user decision 2026-11-12, "Placeholders, build M1 now"). This covers the Tool 1 wording, the category list, the age bands, the danger questions and the ward and landmark lists. Each is marked `PENDING-TOOL1`, `PENDING-TRANSLATION` or `status: placeholder`, and `ProductionReady` refuses all of them. Replacing them later is a gated config change, not code.
- **Triage rule (Build Prompt §10.1; Guide §5):**
  - red if screen 2 = yes or screen 5 = yes;
  - yellow if (screen 2 = I do not know and screen 5 = no) or (category ∈ time-critical set and screen 5 = no);
  - green otherwise.
- Resume window 10 min, on either channel (D4). T2 = after screen 7 (D5, `dispatch_trigger_screen`). Dedup: same category, Chebyshev zone distance ≤ 1, T1 within 15 min, and the earliest call gives T1 (Build Prompt §10.3).
- Ward "Somewhere else" gives an END screen with 999 or 112 (decision 3). The record is kept, flagged `out_of_area` and closed.
- Landmark menu: up to 5 per ward, plus option 6 for free text of at most 20 characters, fuzzy-matched with `pg_trgm`. Low confidence sets `needs_location_callback`, and dispatch uses the ward's zones.
- Screens must be at most the per-network character limit (default 160) in every language, using the GSM 03.38 basic character set only. This is enforced by a CI test and at start-up.
- A new runtime dependency needs a note in `docs/reference/dependencies.md`.
- Each part's PR stays ≤ 100 files and carries its own docs (ADR, runbook, reference, traceability, model card, risk manifest, threats).

## Review Focus

1. **A retried USSD callback during the step that writes an event.** It must produce exactly one event and the same screen (idempotency key `ussd:<provider>:<session>:s<screen>`, plus the step store).
2. **A redial from a withheld number, or one whose MAC key rotated.** It must not resume someone else's incident, and it must not crash. Unknown phone → new incident. Lookup uses the current and previous MAC keys.
3. **A triage bundle whose rows do not cover every input combination, or whose CEL errors at runtime.** Load fails the totality check. A runtime error gives red, flag `triage_rule_error`, and an escalation.
4. **Free-text input containing `*`, non-GSM characters or more than 20 characters.** Parsing is by consumed length rather than splitting on `*`. An over-long answer is re-prompted; it is never truncated silently.
5. **Two bystanders completing screen 7 at the same moment.** Exactly one survivor; neither incident is lost. This is guarded by an advisory lock around the dedup decision (Part B).

    8. on `OutOfArea`, `incident.flagged out_of_area` + `incident.closed {"reason":"out_of_area"}`;
    9. on a callback, `StoreIdentifier` + an answer with `identifier_id` (value `provided` or `same_number`);
